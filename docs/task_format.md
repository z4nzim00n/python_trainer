# Формат задания Python-тренажёра

Образец — папка `tasks/05_lists/01_list_sum_average/`. Прочитай все её
файлы перед тем, как создавать новое задание.

---

## Файлы задания (7 штук)

Каждая папка `tasks/<раздел>/<NN_имя>/` содержит:

| Файл | Назначение |
| --- | --- |
| `README.md` | Условие, метаданные, примеры, команда проверки |
| `main.py` | Стартовая заготовка с `# TODO` |
| `solution.py` | Эталонное решение без комментариев |
| `solution_commented.py` | То же решение с обучающими комментариями |
| `theory.md` | Разбор темы для новичка |
| `tests.md` | Ручная проверка и таблица кейсов |
| `run_testsN_M.sh` | Автотест |

Все файлы генерируются из спецификаций в `specs/`. Руками их правят
только для отладки генератора: следующий `node build.js` перезапишет
изменения.

## Жёсткие правила

1. **Один файл — одна программа.** `main.py` запускается целиком, без
   импортов из соседних заданий и без внешних зависимостей.
2. **Заготовка синтаксически корректна.** `main.py` для задач «напиши с
   нуля» должен компилироваться, даже если печатает `TODO`. Исключение —
   две задачи «исправь ошибку» в `01_basics` (`02_fix_print`,
   `03_fix_indent`): там код намеренно сломан.
3. **Вывод программы — только ASCII.** Никаких русских строк в `print`.
   Русские комментарии в коде допустимы: файлы в UTF-8.
4. **Точный вывод.** Тесты сравнивают байты после нормализации
   `\r\n` → `\n`. В README явно указано, есть ли перенос строки в конце.
   `print(x)` = `\n`, `print(x, end="")` = без `\n`.
5. **Никаких комментариев в `solution.py`.** Как в Школе 21. Комментарии —
   только в `solution_commented.py` и в `# TODO` заготовки.
6. **Стиль.** PEP 8: отступ 4 пробела, `snake_case`, пустые строки вокруг
   функций и классов. Никаких табов.
7. **Детерминированный вывод.** Потоки синхронизируй через `join()` или
   отдельные ячейки результата. Не полагайся на планировщик и порядок
   `set`.
8. **Числа.** Помни, что `/` всегда даёт `float`, а `//` — целое.
   Для двух знаков используй `f"{value:.2f}"`; Python печатает точку
   независимо от локали.
9. **Крайние случаи в тестах.** Пустой ввод, `n = 0`, отрицательные
   числа, деление на ноль, пустой список, отсутствующий файл.
10. **Совместимость.** Python 3.10+. Не используй синтаксис, которого нет
    в этой версии.

## Спецификация

Каждое задание описано блоком в `specs/<файл>.spec`. Блок открывается
`@@TASK`, закрывается `@@END`. Заголовки — строки `поле: значение`,
содержимое секций — до следующего `@@`.

```text
@@TASK
section: 01_basics
dir: 01_hello_world
num: 1_1
title: PY_01_01. Первая программа
topics: `print`, строки
input: Не требуются
@@DESC
Текст условия.
@@EXAMPLES
| Входные данные | Результат работы |
| ------ | ------ |
| — | `Hello, Python!` |
@@THEORY
## Заголовок

~~~python
print("Hello, Python!")
~~~
@@TESTS
| *(нет ввода)* | `Hello, Python!\n` |
@@CASES
run_case_devnull $'Hello, Python!\n'
@@MAIN
print("TODO")
@@SOLUTION
print("Hello, Python!")
@@COMMENTED
# print выводит строку и добавляет перевод строки.
print("Hello, Python!")
@@END
```

### Обязательные поля

| Поле | Что содержит |
| --- | --- |
| `section` | папка раздела, например `05_lists` |
| `dir` | папка задания, например `01_list_sum_average` |
| `num` | номер для имени раннера: `5_1` → `run_tests5_1.sh` |
| `title` | заголовок вида `PY_05_01. Сумма и среднее` |
| `topics` | темы через запятую, в backticks |
| `input` | описание входных данных |
| `desc` | текст условия |
| `examples` | markdown-таблица примеров |
| `theory` | разбор темы |
| `tests` | строки таблицы для `tests.md` |
| `cases` | тело раннера: вызовы `run_case...` |
| `main` | заготовка `main.py` |
| `solution` | эталон `solution.py` |
| `commented` | решение с комментариями |

Генератор проверяет, что все поля заполнены, и падает с понятной ошибкой,
если чего-то не хватает.

## `run_testsN_M.sh` — шаблон

```bash
#!/usr/bin/env bash
set -e
cd "$(dirname "$0")"
source ../../../scripts/lib.sh

compile

run_case "2 2" $'4\n'
run_case "-4 4" $'-16\n'
run_case_devnull $'0\n'

if [ -z "$FAILED" ]; then
  echo "Все тесты пройдены"
else
  echo "Есть проваленные тесты"
  exit 1
fi
```

### API `scripts/lib.sh`

- `compile` — проверяет синтаксис `$SOURCE_FILE` (по умолчанию
  `main.py`) через `compile(...)`, не создавая `__pycache__`.
- `run_case "вход" "ожидание"` — вход через `printf` (добавляет `\n`).
- `run_case_noeol "вход" "ожидание"` — без завершающего `\n`.
- `run_case_devnull "ожидание"` — пустой stdin (EOF сразу).
- `run_case_args "аргументы" "вход" "ожидание"` — запуск с аргументами.
- `check_file "путь" "ожидание"` — проверяет содержимое файла,
  созданного программой.

Интерпретатор ищется в порядке `PYTHON` → `python` → `py` → `python3`.
Если найденный `python` оказался Python 2, задания упадут на синтаксисе
`f`-строк — проверьте `python --version`.

Ожидание — точные байты:

```bash
run_case "2 2" $'4\n'          # print
run_case "2 2" "4"             # print(..., end="")
run_case $'a\tb\nc' $'3\n'     # табы и переводы строк
```

### Файловые задания

Создай файлы до вызова `run_case` и удали их через `trap`:

```bash
trap 'rm -f input.txt output.txt' EXIT
printf 'hello\n' > input.txt
run_case "input.txt" $'hello\n'
check_file "output.txt" "hello"
```

Относительные пути считаются от папки задания: раннер делает `cd` в неё.

## Порядок проверки

```bash
cd tasks/<раздел>/<задание>
SOURCE_FILE=solution.py bash run_testsN_M.sh
SOURCE_FILE=solution_commented.py bash run_testsN_M.sh
```

Оба запуска должны напечатать `Все тесты пройдены`.

Проверка заготовки:

```bash
SOURCE_FILE=main.py bash -c 'source ../../../scripts/lib.sh; compile'
```

Для двух задач «исправь ошибку» эта команда может падать — это ожидаемо.

Проверка всех заданий:

```bash
cd python_trainer
bash scripts/run_all.sh --solution
bash scripts/run_all.sh --commented
```

Ожидаемый результат — `Пройдено: 71/71`.

## theory.md — что писать

Хороший разбор содержит:

1. **Идею** — зачем нужна тема, где пригодится.
2. **Минимальный пример** на Python в `~~~python`.
3. **Разбор** — что делает каждая строка.
4. **Таблицу** сравнения или шпаргалку.
5. **Частые ошибки** — 3–5 пунктов с последствиями.
6. **Крайние случаи** — что будет при `0`, пустом списке, `None`.

Не пересказывай учебник. Пиши то, что нужно именно для этого задания.
